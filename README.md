# AmneziaWG 3.1

Личный VPN на VPS `178.62.199.241`. Проект исторически называется `proxy_tg`,
но теперь содержит только файлы AmneziaWG. MTProxy, Dante и оба Xray удалены
с сервера и из текущей версии проекта 23 ноября 2026 года.

## Подключение и статус

| Доступ | Порт |
| --- | --- |
| AmneziaWG 3.1 | UDP 585 |
| SSH для администрирования | TCP 22 |

VPN работает отдельной службой `awg31.service`; автозапуск включён.
Пользователь подтвердил работу подключения. На сервере также зафиксированы
handshake и трафик реального клиента. Изолированным тестом проверены DNS,
HTTPS, выход через IPv4 VPS и передача данных в обе стороны.

Клиент iPhone: официальный AmneziaVPN 5.0.2.1 или новее. Импортировать закрытый
файл `.conf` или отсканировать его QR-код. Профиль и QR содержат приватный ключ
и в репозитории не хранятся. SSH-данных в гостевом профиле нет.

## Файлы проекта

- `amneziawg31/awg31.service` — служба systemd.
- `amneziawg31/manage.py` — настройка интерфейса и правил VPN.
- `amneziawg31/rules.json` — правила firewall/NAT только для этого VPN.
- `amneziawg31/manifest.json` — версии исходников, toolchain и SHA256 бинарников.
- `amneziawg31/rollback.sh` — отключение VPN и удаление его сетевых правил.

Ключи, `server.conf`, клиентские профили, QR-коды и резервные копии остаются
в закрытых каталогах вне Git. Старый код доступен в истории репозитория.
Автодеплои старых прокси отключены, их workflows удалены. Автодеплой VPN
не настроен: push не изменяет сервер.

## Реализация

Установка выполнена через SSH по [официальной инструкции AmneziaWG-Go](https://docs.amnezia.org/ru/documentation/instructions/install-amneziawg-go/),
без приложения на Mac, Docker и модуля ядра.

| Компонент | Версия |
| --- | --- |
| AmneziaWG-Go | `08fe3d33bbb116be09a6183d02609311b8b0c9e8` |
| AmneziaWG-tools | `v3.1.20260812`, commit `ee0f0a9aa34ff0a0da4b3433b9512781cfe02843` |
| Источник параметров | `amnezia-client/5.0.2.1`, commit `327e5985df0ef16ea03058b611e171b1d3bc0420` |
| Сборочный Go | `1.25.12`, официальный архив с проверенной SHA256 |

В [официальных константах клиента](https://github.com/amnezia-vpn/amnezia-client/blob/5.0.2.1/client/core/utils/constants/protocolConstants.h)
`awgV3 = "3.1"`. Проверены активные `HeaderProtectionKey`, `RandomTrailers`,
`DisableCookies` и `S1`–`S4 = 12`.

Сервер: Ubuntu 26.04.1, x86_64, KVM, 1 CPU, номинально 1 GB RAM.
Ubuntu 26.04 оставлена по указанию владельца и не входит в официальный список
ОС Self-hosted. На ней фактически прошли сборка и целевые проверки userspace.
Ядро `7.0.0-43-generic` сохранено; обновления ОС и reboot не выполнялись.
Временный компилятор, исходники и кэши после установки удалены.

## Сеть и обслуживание

Интерфейс `awg31`, подсеть `10.77.31.0/24`, MTU 1280. IPv4 forwarding включён
через `/etc/sysctl.d/90-awg31-forward.conf`; NAT разрешён только для VPN через
`eth0`. Доступ гостя к самому VPS и частным сетям запрещён. Прочий транзит
запрещён маркированным правилом, как и до установки VPN.

IPv6 клиента направлен в туннель через `::/0`. Публичный IPv6 сервер не
предоставляет; IPv6 forwarding не включён. Блокировка обхода проверена
изолированным Linux-клиентом; отдельный автоматический тест iOS не проводился.

```sh
systemctl status awg31.service --no-pager
/usr/local/bin/awg31 show awg31
journalctl -u awg31.service -n 30 --no-pager
```

Рабочие файлы на сервере: `/opt/awg31` (каталог `0700`, секреты `0600`).
Бинарники: `/usr/local/sbin/awg31-go` и `/usr/local/bin/awg31`.
Файлы репозитория сами по себе не восстанавливают закрытую конфигурацию.
Бот, мониторинг и другие независимые приложения VPS очисткой не затронуты.

## Восстановление и отключение

Защищённая копия перед удалением старых прокси:
`/var/backups/proxy_tg/retired-proxies-20261123T133126Z`.
Архив проверен чтением, сохранены контрольные суммы, units и данные
системных аккаунтов. Там же есть копия конфигурации AWG до очистки.

Для отключения только VPN:

```sh
sudo /opt/awg31/rollback.sh
```

Скрипт отключает службу и удаляет её unit, sysctl-файл и правила VPN.
Ключи остаются в закрытом каталоге. Пока forwarding включён, сохраняется
защитный запрет постороннего транзита.

Для возврата IPv4 forwarding к исходному `0` сначала проверить, что от него
не зависят появившиеся позднее сервисы, затем выполнить:

```sh
sudo /opt/awg31/rollback.sh --restore-forwarding
```

Старые снимки firewall целиком не восстанавливать. Возврат удалённых прокси
требует отдельного восстановления их файлов и аккаунтов из защищённой копии.
