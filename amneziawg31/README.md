# AmneziaWG 3.1

Проверенные файлы действующей userspace-службы на VPS. Установка выполнена
23 ноября 2026 года через SSH, без приложения AmneziaVPN на Mac, Docker,
обновления ОС/ядра и перезагрузки сервера.

## Состав

- `awg31.service` — отдельная служба systemd.
- `manage.py` — настройка интерфейса и добавление/удаление только правил AWG.
- `rules.json` — адресные правила firewall и NAT.
- `rollback.sh` — остановка и отключение только новой службы.
- `manifest.json` — закреплённые исходники, toolchain и SHA256 установленных
  бинарников. Это контрольные суммы конкретной сборки.

Ключи, `server.conf`, клиентские профили, QR-коды и резервные копии хранятся
отдельно. Эти файлы репозитория не содержат готовых учётных данных и сами
по себе не восстанавливают сервер. Скрипты выполняют привилегированные
сетевые операции; не запускать их на другом сервере без проверки путей,
портов, подсетей и исходного состояния forwarding.

## Версии и способ установки

Использована [официальная инструкция сборки AmneziaWG-Go](https://docs.amnezia.org/ru/documentation/instructions/install-amneziawg-go/).

| Компонент | Закреплённая версия |
| --- | --- |
| AmneziaWG-Go | `08fe3d33bbb116be09a6183d02609311b8b0c9e8` |
| AmneziaWG-tools | `v3.1.20260812`, commit `ee0f0a9aa34ff0a0da4b3433b9512781cfe02843` |
| Go | `1.25.12`, официальный архив с проверенной SHA256 |
| Источник параметров | `amnezia-client/5.0.2.1`, commit `327e5985df0ef16ea03058b611e171b1d3bc0420` |

Режим 3.1 подтверждён соответствием официальному установщику и проверкой
активных параметров: `S1`–`S4 = 12`, `HeaderProtectionKey`,
`RandomTrailers = on`, `DisableCookies = on`, диапазоны таймеров.
В [константах клиента](https://github.com/amnezia-vpn/amnezia-client/blob/5.0.2.1/client/core/utils/constants/protocolConstants.h)
`awgV3` имеет значение `3.1`. Само название бинарника или его встроенная
строка версии не использовались как доказательство протокола.

На сервере бинарники находятся в `/usr/local/sbin/awg31-go` и
`/usr/local/bin/awg31`; защищённые данные — в `/opt/awg31` (каталог `0700`,
ключи и профили `0600`).

## Окружение и сеть

- Ubuntu 26.04.1, x86_64, KVM, 1 CPU, номинально 1 GB RAM.
- Ядро `7.0.0-43-generic` сохранено.
- Ubuntu 26.04 отсутствует в официальном списке поддерживаемых ОС
  Self-hosted; оставлена по указанию владельца. Сборка и целевая проверка
  userspace-компонента на ней прошли.
- Отдельный UDP-порт `585`, интерфейс `awg31`, подсеть `10.77.31.0/24`.
- NAT только для новой подсети через `eth0`; MTU `1280`.
- IPv4 forwarding включён отдельным `/etc/sysctl.d/90-awg31-forward.conf`.
  До установки он был выключен. Маркированное правило сохраняет запрет
  постороннего транзита; исключение разрешено для нового VPN.
- VPN-клиенту запрещён доступ к самому VPS и частным сетям.
- IPv6 forwarding не включался. Клиент направляет `::/0` в туннель;
  публичный IPv6 через VPS не предоставляется, обход VPN блокируется.
- MTProxy, Dante, Xray REALITY, Xray WS и SSH не перенастраивались
  и не перезапускались. Правило MSS 1024 для TCP 8443 сохранено.

## Результаты целевых проверок

**PASS:** настоящий handshake с отдельным клиентом в network namespace
на VPS, DNS и HTTPS через туннель, внешний IPv4 сервера, трафик в обе
стороны, блокировка IPv6-обхода и SSH самого VPS через туннель.
Тестовый peer, его приватные ключи и namespace после проверки удалены.

**PASS:** автозапуск настроен; после перезапуска только новой службы
остался гостевой peer iPhone и сохранились параметры 3.1. Перезагрузка
всего VPS для проверки автозапуска не выполнялась.

**PASS:** MTProxy — аутентифицированный FakeTLS handshake; Dante —
MTProto resPQ и отказы анониму, неверному паролю и назначению вне Telegram;
оба Xray — HTTPS. Хеши конфигураций, PID и время запуска прежних служб
остались прежними. Ключи в журнале новой службы не обнаружены.

**NOT CONFIRMED:** контрольный UDP-пакет с Mac не наблюдался на публичном
интерфейсе VPS. Причина не установлена; это не доказывает дефект AWG.
Firewall провайдера через API не проверялся. Внешний handshake не подтверждён.

**NOT RUN:** физический iPhone через МегаФон, Telegram/медиа, браузер,
DNS/IPv6 на iOS, восстановление после авиарежима и контрольные 15 минут.
Успешный тест внутри VPS не заменяет эти испытания; полная приёмка ожидается.

## iPhone

Гостевой `.conf` импортируется в официальный AmneziaVPN для iOS
версии 5.0.2.1 или новее. Импорт параметров проверен по
[официальному коду](https://github.com/amnezia-vpn/amnezia-client/blob/5.0.2.1/client/core/controllers/selfhosted/importController.cpp);
реальное подключение iPhone ещё не проверено. Обычный WireGuard не подходит.

Передать закрытый профиль через AirDrop или сканировать закрытый QR-код.
Файл и QR содержат приватный ключ: не добавлять их в Git и не прикладывать
к issues. Для проверки выключить Wi-Fi, другие VPN и прокси Telegram,
подключиться через МегаФон и проверить перечисленные выше сценарии.
Профиль не содержит SSH-ключа и доступа к управлению сервером.

## Резервная копия и откат

Исходная защищённая копия на VPS:
`/var/backups/proxy_tg/before-awg31-20261123T114851Z`.
Контрольные суммы проверены до установки. Актуальный baseline, результаты
проверок и исходные скрипты выполненной установки сохранены root-only
в `/opt/awg31`, скрипты — в `/opt/awg31/deployment`.

Для остановки только AWG:

```sh
sudo /opt/awg31/rollback.sh
```

Скрипт отключает службу и удаляет её unit, sysctl-файл и VPN-правила.
Пока forwarding включён, сохраняется маркированный запрет постороннего
транзита. Ключи и аудит остаются в закрытом каталоге для восстановления.
Docker и существующие прокси не затрагиваются.

Полный возврат forwarding к исходному `0` допустим после проверки,
что появившиеся позднее сервисы от него не зависят:

```sh
sudo /opt/awg31/rollback.sh --restore-forwarding
```

Этот режим также удаляет оставленный запрет транзита. Не восстанавливать
старый firewall целиком. После отката проверить SSH и существующие прокси.

Изменения этой папки не входят в `push.paths` существующих deploy-workflows;
самостоятельный автодеплой AWG не настроен.
